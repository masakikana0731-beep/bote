## 3. モデルの仕組み

1. **強さスコア**：LightGBM で各艇の「上位に来やすさ」のスコアを出す。目的関数は **1〜3着の Plackett-Luce 尤度を直接最大化**（2026-10-14 に LambdaRank から変更。確率の当てやすさを直接学習するほうが精度が良かった）
2. **1着確率**：6艇のスコアを softmax で確率にする
3. **2着・3着の確率**：1着を除いた艇で同じ計算を繰り返す（Plackett-Luce）。ただし段階ごとに「温度」を変える
   - 学習結果：1着 1.10 / 2着 0.72 / 3着 0.49（旧モデル 1.06 / 0.75 / 0.54）
   - 2着・3着ほど実力差どおりに決まりにくい、という意味。素のHarville法（温度を変えない）はこれを過大評価する
4. **3連単120通りの確率** ＝ 1着確率 × 2着確率 × 3着確率

学習の期間分け:
- 学習：2023/10/1〜2026/4/30（135,880レース）※最初の3か月は過去成績を溜めるためだけに使用
- 検証：2026/5/1〜7/14（11,187レース）… 木の本数と温度を決める
- テスト：2026/7/15〜10/12（13,588レース）… 一度も使っていない期間で評価

## 4. モデルの精度（テスト期間）

| 指標 | 学習モデル | コース別勝率だけ | 市場（人気） |
|---|---|---|---|
| 1着を当てる率 | **57.1%** | 54.1% | – |
| 実際の3連単の順位（中央値） | 10位 | – | **9位** |
| 実際の3連単が上位10位以内 | 51.1% | – | **54.5%** |
| 3連単の対数尤度（オッズのある3,106R） | -3.89 | -4.21 | **-3.76** |

**市場（オッズ）のほうが少し正確**。オッズには展示航走の気配・記者情報・大口の資金などが織り込まれているため。
モデルが「期待値1以上（お得）」と判断した買い目でも、実際の回収率は65〜71%だった。

同時に直した不具合：
- **本番で事前値（コース別の平均）が使われていなかった**。meta.json のキーが文字列になり、`priors["win"].get(int(c))` が常に既定値になっていた → 本番の予想は、バックテストで評価したモデルと少し違う計算をしていた。`Model` で読み込むときに整数に戻すよう修正
- `_rolling_by` で、複数キーの `groupby(sort=False)` の並びが崩れ、集計値が別の行に付くことがあった（既存の特徴量は影響なし、追加した「その場での成績」で発覚）。`sort=True` にして並びの一致を確認するようにした
- 学習時と本番（snapshot＋live_features）で全特徴量が一致することを、テスト期間の90レースで確認済み

### 2026-10-15 進入コースの情報漏れを修正（重要）

- 公式の競走成績にある「進入コース」はレース後に分かる値。スタート展示の進入と違う艇が **約5%（レースの約12%）** ある
- それまでの学習・評価は競走成績の進入を使っていたので、テスト期間の成績が良く見えすぎていた
  - v4 のテスト期間の対数尤度：-3.796（漏れあり）→ **-3.809（展示の進入）**
  - 「モデルと市場の混合で、市場より割安に見える3連単を買う」戦略は、漏れありだと回収率 200〜400% に見えたが、
    展示の進入で計算し直すと、割安に見える目そのものがほぼ無くなった（期待値≥1.0 の目は 0点）
- 修正：直前情報（data/before.parquet）があるレースは、学習・評価・本番のすべてで展示の進入コースを使う（`load_history`）。
  過去成績の集計も同じ定義なので、学習時と本番の特徴量は一致する（確認済み）
- 直前情報が無い期間（収集中）は競走成績の進入のまま。評価するときは、その期間の直前情報がそろっていることを確認すること

### 2026-10-16 締切前オッズでの紙上の売買（最初の1日半、155レース）

モデルの確率 × オッズ（期待値）が高い1点を選んだとき、選んだ目のオッズが締切前→確定でどう動いたか：

| 券種 | 締切前のオッズで選ぶ：確定/締切前（中央値） | 確定オッズでの期待値（平均） | 回収率 | 確定オッズで選ぶ（現実には不可能）：確定/締切前 | 回収率 |
|---|---|---|---|---|---|
| 単勝（5分前・EV≥1.0） | 0.41 | 0.94 | 36%（130点） | 1.49 | 138% |
| 複勝（5分前・EV≥1.0） | 0.43 | 0.68 | 86%（74点） | 1.83 | 131% |
| 拡連複（5分前・EV≥1.0） | 0.52 | 0.85 | 64%（152点） | 1.35 | 102% |
| 3連単（混合・EV≥0.9） | 0.71〜0.76 | 0.61〜0.63 | （10点） | – | – |

- 締切前に「割安」に見えた目は、確定までにオッズが半分前後に下がる（売上の小さい券種ほど大きい）
- 確定オッズで選ぶシミュレーションは「締切直前にオッズが上がった目」を選んでいて、それが回収率を押し上げていた
- → 単勝・複勝・拡連複が良く見えた最適化の結果（6b）は、確定オッズを先に知っている前提の見かけだった可能性が高い
- 1日半なので回収率そのものは当てにならない。オッズの動きの傾向は全券種で一貫している。記録は継続中

## 6. 最適化の方法と結果

- 3,000通りのパラメータをランダムに生成
- テスト期間を前半（7/15〜8/28）と後半（8/29〜10/12）に分け、**前半と後半の悪いほうの回収率**で順位付け（片方だけ良い設定を除くため）
- さらに日単位のブートストラップ（5,000回）で回収率の90%区間を計算
- 条件：1日3,000円・最大10R

| 設定 | 的中率 | 回収率 | 90%区間 | プラスになる確率 | 上位2回の的中を除くと | 最長連敗 |
|---|---|---|---|---|---|---|
| 当たる楽しさ | 25% | 86% | 74〜99% | 4% | 83% | 27R |
| バランス | 19% | 99% | 75〜125% | 48% | 90% | 19R |
| 一発狙い | 6% | 137% | 82〜200% | 85% | 106% | 44R |
| 超大穴（参考） | 2% | 178% | 57〜330% | 83% | 62% | 151R |
| 人気のみ（参考） | 26% | 79% | 69〜89% | 0% | 77% | 25R |

### 注意（結果の読み方）
- 3,000通りの中から良かったものを選んでいるので、**同じデータでの成績は実力より良く見える**（選択バイアス）。プラスになる確率も楽観的な値
- 「一発狙い」「超大穴」は的中が少なく、数回の大当たりで結果が決まっている
- 90日・1日3場の抜き取り・確定オッズでの検証。実運用は締切数分前のオッズで買うのでずれる
- 期間が変われば結果も変わる。仮想モードで実際に試して確認するのが確実

### 注意（この結果は額面どおりに受け取れない）
- **単勝・複勝・拡連複が良く見えるのは、確定オッズで選んで確定オッズで払い戻している影響が大きいと推測**
  - 期待値の下限（確定オッズ×確率）を上げるほど回収率が上がるが、これは売上の小さい券種だけで起き、3連単では起きない
  - 確定オッズは締切後に決まる値。実運用では締切数分前のオッズで判断するので、「たまたま締切直前に上がったオッズ」を選ぶことはできない
  - 売上の小さい券種は自分の購入でもオッズが下がる（未検証）
- 旧モデルで前半一番良かった設定（3連単1点・回収439%）は後半で1回も当たらなかった。前半の成績で選ぶと見かけが大きく良くなる（上位20件平均：前半383% → 後半167%）
- 新モデルで単勝・複勝・拡連複がさらに良く見えるのは、確率が正確になったぶん「確定オッズのゆがみ」をより拾えている可能性がある。これが本物の利益か、確定オッズを使った影響かは区別できない
- 売上の大きい3連単・3連複・2連単・2連複は、新旧どちらのモデルでも全候補の平均が100%未満
- 確かめるには、仮想モードで「判断時のオッズ」と「確定オッズ」を両方記録して比べる必要がある

## 7. 作り直し方

Windows では `PYTHONUTF8=1` を設定して実行する。

```bash
pip install -r requirements-ml.txt
python -m boatbot.history download --start 20230701 --end 20261012   # 公式一括データ（初回のみ・数時間）
python -m boatbot.history build                                       # data/history.parquet
python -m boatbot.ml train && python -m boatbot.ml evaluate
python -m boatbot.backtest fetch-odds --days 90 --venues-per-day 3    # 戦略検証用オッズ
python -m boatbot.optimize prepare && python -m boatbot.optimize search --n 3000
python -m boatbot.backtest fetch-odds-multi --workers 4                # 全券種オッズ
python -m boatbot.optimize2 prepare && python -m boatbot.optimize2 search --n 20000 --jobs 8
python -m boatbot.optimize2 report                                    # docs/results/opt2_report.json
```
学習済みモデルは `models/` に入っています（リポジトリに同梱）。ただし本番の予想には過去成績の集計が必要なので、自宅PCでも最初に `history download` と `build` を一度実行してください（数時間）。
アプリ起動中は毎朝、前日分の公式データを自動で取り込み、過去成績の集計を更新する（モデルの再学習は手動）。
